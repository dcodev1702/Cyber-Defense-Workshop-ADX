# Changelog

## Unreleased

- Fixed a silent data loss defect in `scripts/Backup-LocalKustoSnapshot.ps1`. The script chose its restorable payload by taking the most recently written directory under `data/local-export`, which meant every archive it produced shipped the 48-table, 358,621-row copy left behind by the last Azure Data Explorer sync rather than the 79-table, 623,832-row database it was supposedly backing up. Nothing reported a problem, because the script never compared the payload to the database or to the manifest. The payload is now taken from `data/generated`, which is the current source of truth, and the script refuses to produce an archive unless the payload covers every table in `metadata/tables.manifest.json`. Pass `-UseLocalExport` to select an Azure Data Explorer export deliberately, or `-AllowIncompleteExport` to accept a partial archive knowingly.
- Made backup archives self-contained. They now carry the table schemas and manifest alongside the data, so restoring no longer depends on a matching checkout being present. The backup manifest records the payload source and both the exported and declared table counts.
- Stopped the restore script reporting work it had not done. In extract mode it announced the container name and port it was about to use, and finished with "Restore container and working files removed", while starting and removing nothing. Extract mode now invokes no external command at all, and the container options moved into their own parameter set so `-KeepContainer`, `-ContainerName`, `-HostPort`, `-Memory`, and `-Image` are rejected outright rather than silently ignored when combined with `-ExtractPayloadTo`. Misleading output and silently discarded options are both worth treating as defects in a tool someone reaches for when the workshop is already broken.
- Documented restoring everywhere the repository tells you to take a backup. Five documents instructed the reader to create an archive and none said how to use one, and the container-replacement guidance routed recovery through `Copy-StudentAdxToLocalKusto.ps1 -ForceRecreate`, which re-copies from the Student cluster in Azure. That path needs cluster access and an entitled sign-in, so the documented recovery was unavailable in precisely the situation it existed for: a venue with no usable connectivity, or a cluster that no longer exists. The backup was written and then abandoned. `Restore-LocalKustoSnapshot.ps1 -ExtractPayloadTo` now puts the archive's telemetry and schemas back on disk for `Import-GeneratedDataToKustainer.ps1` to load, giving an offline rebuild, and that route is documented in the README, the Cloudflare access guide, the instructor guide, the Cloudflare infrastructure README, and the IaC setup guide.
- Added `scripts/Restore-LocalKustoSnapshot.ps1`, so restoring is a repeatable operation rather than something reconstructed by hand under pressure. It rebuilds the database in a throwaway container on a spare port, reconciles the restored row count against the archive, refuses to run against the workshop container, and cleans up after itself. Verified against the current archive: 79 of 79 tables and 623,832 of 623,832 rows, table-for-table identical to the live cluster, with the workshop's credential access queries returning the expected results.
- Recorded why the NDJSON payload is what makes an archive restorable. The emulator registers a persistent database inside the container rather than in the mounted state directory, so a fresh container cannot attach persisted state another container wrote; `.create database ... persist` fails with an internal service error and `.attach database` reports a missing V11 pointer. The persisted state in an archive is therefore only useful for restoring files under the same container instance, and structural validation of the ZIP proves nothing about whether it can be restored.
- Made the tenant data safeguard enforced rather than advisory. `metadata/field-profiles/` is tracked because those profiles are what make the generated telemetry reproducible, which leaves them as the one path by which live tenant data could reach a public repository. A tracked `.githooks/pre-commit` now blocks any commit that stages raw capture data from `sample/`, and runs the profile scan whenever a field profile is staged; `scripts/Install-WorkshopGitHooks.ps1` activates it for a clone, since Git does not version `.git/hooks`. Because a local hook can be skipped with `--no-verify` and does nothing until installed, `.github/workflows/telemetry-safety.yml` runs the same scan on every push and pull request, and additionally fails if raw telemetry or the generated package is ever tracked, or if the manifest, schemas, and profile overrides disagree.
- Fixed `scripts/Test-FieldProfileSafety.ps1`, which had an absolute path to one machine and so could not run for anyone else or in CI. It now resolves the profile directory relative to the script, accepts `-ProfileDirectory` and `-Quiet`, and reports which columns failed and how to regenerate them.
- Stopped tracking `data/generated/`. The package is roughly 900 MB of NDJSON and is now reproduced deterministically from the committed schemas, field profiles, and fixed random seed, so the generator is the artifact rather than its output. `DeviceProcessEvents.json` had reached 95.7 MB against GitHub's 100 MB hard limit, and every column added to that table moved it closer. `data/scenario-summary.json` stays tracked because it documents the scenario rather than carrying bulk data.
- Documented the offline build path in the README: generate, import to Kustainer, then run the package, quality, and identity gates. Also documented how to refresh the field profiles and the requirement that `Test-FieldProfileSafety.ps1` reports clean before profiles are committed.
- Corrected the expected total row count in the student lab setup guide from roughly 629,000 to roughly 624,000 to match the regenerated package.
- Added `scripts/Import-GeneratedDataToKustainer.ps1`, which creates each table from its schema, applies a JSON ingestion mapping, clears existing rows, ingests the generated NDJSON from the read-only mount, and reconciles ingested row counts against the files on disk. It talks to the emulator's REST endpoint directly because the local cluster is unauthenticated, whereas the shared management helper always demands an Azure bearer token.
- Made ambient `DeviceNetworkInfo` rows agree with the per-device inventory records. Both now draw from the same adapter catalog and build the hardware address from the vendor's own IEEE OUI, so identifying hardware from the first three octets always matches the reported vendor. Previously the two paths used different vendor lists, which produced adapters whose OUI contradicted their vendor.
- Replaced the placeholder tenant and subscription identifiers with real random GUIDs. One tenant GUID now backs every table that carries a tenant column, and Azure resources are spread across a fixed pool of 25 subscriptions selected by hashing the resource, so a device or storage account keeps the same subscription across every table that references it. Added `scripts/Test-WorkshopIdentityInvariants.ps1` to enforce both rules; the all-zero GUID is tolerated as a well-known management group and Microsoft Graph placeholder.
- Filled the gaps that made several tables unusable, using real product vocabularies rather than invented values:
  - `DeviceNetworkInfo` now carries a complete adapter record. Vendors are real NIC manufacturers paired with their actual IEEE OUI prefixes, and the MAC address is built from that prefix so hardware identification from the first three octets agrees with the reported vendor. Gateways and DHCP servers derive from the device subnet, and DNS resolvers follow the site. Virtual hosts get hypervisor adapters and physical hosts get real silicon. This table is written one row per device by the inventory loop, not by the ambient branch, which is why it had stayed empty.
  - Endpoint tables now report file version metadata for known binaries. Signed Microsoft binaries carry their shipping resource strings, and the credential access tooling in the scenario carries its real authorship, which is the pivot that separates it from living-off-the-land activity.
  - `AlertInfo` and `AlertEvidence` ambient alerts now carry real Microsoft Defender and Microsoft Sentinel titles with the MITRE ATT&CK tactic and technique identifiers each maps to. `AttackTechniques` had been hard-coded empty, which made technique-based hunting impossible.
  - `DeviceTvmSecureConfigurationAssessmentKB` and `DeviceBaselineComplianceAssessmentKB` are driven by a catalog of real Microsoft, CIS, and DISA STIG security configuration entries with rationale, risk description, CCE reference, and remediation steps.
  - `AppGenAIContent`, `IntuneDevices`, and `CloudAppEvents` gained generator branches. `AppGenAIContent` emits OpenTelemetry gen_ai spans for the same agents declared in `AgentsInfo`, so a hunt can pivot from an agent registration to what the agent actually did.
- Recorded the columns the workshop deliberately populates even though the source tenant leaves them empty in `metadata/profile-overrides.json`, covering agent governance, directory enrichment on the identity tables, and Azure resource association on `DeviceInfo`. The generator and the quality gate both read that file.
- Fixed three latent defects in the generator: a comma-precedence bug that made an arithmetic expression operate on an array, a hardware address format that produced malformed octets past device 255, and an `[array]::IndexOf` lookup that rescanned the whole fleet on every iteration.
- Stopped field profiles from carrying tenant data. Suppressing identity and free-text columns by name missed columns whose values embed tenant identifiers, such as `SourceAgentId`, which carries Azure resource IDs containing a live subscription GUID; a scan of the committed profiles found 70 such columns. Captured vocabularies are now dropped when any value contains an embedded GUID, a subscription, resource group or tenant path, a UPN, an address, a bearer token or JWT, or a long hex string. Version columns are exempt from the address test so product versions are not mistaken for an IP. `scripts/Test-FieldProfileSafety.ps1` enforces this and now reports clean, with 762 of the original 819 vocabularies retained.
- Made the generator consume the real field profiles: columns that production populates but that carry no safe vocabulary now receive a shape-matching synthetic value at the observed fill rate, and columns empty in production are cleared on ambient rows unless listed in the new `metadata/profile-overrides.json`, which the generator and the quality gate both read.
- Removed the fallback record that seeded every table lacking scenario evidence with a fabricated `WorkshopBaseline` action and application plus endpoint and identity columns most tables do not declare. Every table now reaches its row count through the normal generator.
- Rebuilt `AgentsInfo`, which had no generator branch and emitted 32 of its 39 columns empty. It now generates a declared-agent inventory with model, endpoint, MCP server, skill, permission, guardrail, trigger, data source, and owner detail, with instruction and tool fill rates tracking the real inventory at 52 and 40 percent.
- Added `scripts/Test-SyntheticDataQuality.ps1`, which scores generated tables against the real field profiles and reports sparse, overfull, and out-of-vocabulary columns.
- Added `scripts/Export-WorkshopTelemetryProfiles.ps1`, which derives per-column field profiles for every workshop table from real telemetry so the synthetic generator can reproduce production shape instead of inventing values. Rows are merged from three sources: the curated captures in `sample/`, Log Analytics workspace `DIBSecCom`, and Defender XDR advanced hunting for the tables that exist only in XDR. Profiles record fill rate, cardinality, weighted value vocabulary, detected format pattern, and numeric or length bounds, and they explicitly mark columns that are empty in production so the generator can leave them empty by design rather than by oversight.
- Generated field profiles for 69 of the 79 tables from real telemetry. The remaining 10 emit no data anywhere in the tenant and are driven from their documented Microsoft Learn schemas instead.
- Replaced `DeviceTvmBrowserExtensionsKB` with `AppGenAIContent` in the table manifest, schemas, and parallel generator.
